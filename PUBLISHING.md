# Publish without leaking personal metadata

The repository should remain private until this checklist is completed. A pseudonymous commit is not a guarantee that an existing GitHub account is unlinkable to its owner.

## Prepared bundle route

The delivery bundle contains a normal Git history with explicit pseudonymous author and committer metadata. To import the bundle into an empty target using native PowerShell and the user's existing Git authentication:

```powershell
git clone .\DAIA-public-safe.bundle DAIA
Set-Location DAIA
git remote set-url origin https://github.com/joindaia/DAIA.git
python scripts/privacy_guard.py --history
git push -u origin main
```

The push is deliberately **not forced**. If the remote has gained unrelated work, stop and review it; do not overwrite the repository. These commands do not change repository visibility. Review remote history before making anything public.

A ZIP is an alternate source snapshot, not a Git history. Run `scripts/prepare-git.ps1` inside an extracted snapshot to create a local pseudonymous initial commit. The script refuses an existing Git worktree and never pushes or changes hosting settings.

## Future commits

Configure the actual GitHub-provided noreply address locally, using the public alias rather than a legal name. Enable the account's email-privacy and private-email-push protections where available. Check both author and committer, including merge commits generated by third-party tools. Connected tools may inherit the account's configured author and committer metadata rather than a local noreply configuration. Account-attributed commits are not necessarily pseudonymous; review the actual remote history before publication. The history privacy tripwire deliberately continues to flag non-placeholder email addresses, even when account-attributed commits were authorized.

```powershell
git config --local user.name joindaia
git config --local user.email 328068061+joindaia@users.noreply.github.com
git config --local user.useConfigOnly true
python scripts/privacy_guard.py --history
```

The GitHub user ID and alias in this noreply address are public identifiers. They are included intentionally, not as evidence of anonymity.

## Full publication checklist

Review **all reachable commit objects**, their author/committer names and emails, messages, tags and every historical tree, not just current HEAD. Run a dedicated mature secret scanner over full history as well as the local guard. The guard detects only some formats and cannot prove absence of secrets. A local optional `DAIA_PRIVATE_DENYLIST` can hold newline-separated private strings for scanning; do not commit that list or paste its matches into logs.

Review `.env` files, databases, local paths, test fixtures, screenshots, documentation examples, copied conversations, package metadata, generated lockfiles, source maps, build archives, CI logs, artifacts, issue bodies and PR discussions. Examine linked profiles, domains, organizations, sponsorship configuration and security contact details for unwanted personal linkage.

Use a dedicated public project identity/contact if stronger separation is needed. Do not fabricate human contributors. Keep sensitive details out of CODEOWNERS, license headers and author fields; the public handle is sufficient for this scaffold.

Select a license deliberately. Enable branch rules requiring review and successful CI; protect workflow/auth/policy changes and release environments. Enable private vulnerability reporting if supported. Confirm those settings actually apply to the repository visibility/plan; checked-in policy files do not enforce them.

The bootstrap did not alter repository visibility, branch rules, security-reporting settings or account-level email preferences.

Sources: [GitHub commit email privacy](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address), [Git commit API metadata](https://docs.github.com/en/rest/git/commits), [Actions security](https://docs.github.com/en/actions/reference/security/secure-use).
