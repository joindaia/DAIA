# Native Windows audit and private MCP pilot

Scope: coordinator, persistence, signatures, policy/checker, HTTP/MCP adapters,
CLI/helpers, tests, and configured CI. Local execution on Windows with Python 3.14.
This is an engineering audit and test record, not production security certification.

## Desktop contributor follow-up

The local stdio helper now owns registration, envelope checking and signing. Its
consent budget, stop state, lease and pending receipt survive process restarts.
The coordinator adds an authenticated own-grant/lease status tool (eight raw tools);
the desktop helper exposes five simpler tools. Native Codex app-server 0.144.3 discovered
all five using the installed project configuration, without model inference or a claim.
The restarted coordinator passed authenticated discovery over the existing private tailnet.

Validation: 82 tests passed, one POSIX-permission test skipped on Windows. The new
tests cover real stdio subprocess -> SDK HTTP -> coordinator submission and process
restart, committed-but-lost claims and receipts, consent expiry, failed release,
duplicate-host locking, tampered envelopes, revocation, and preserving host settings.
The deterministic demo and PowerShell syntax checks passed. `uv.lock` resolves 45
packages across supported Python versions, with public PyPI sources and hashes;
the selected dev/MCP dependencies installed from that frozen lock. `pip-audit
--skip-editable` reported no known vulnerabilities; the local project is not covered
by the package advisory database. License review remains outstanding.

The two-machine model pilot below predates this helper. A new desktop model turn and
remote-machine helper run remain separate acceptance checks. No general contributed
code execution, isolated verifier, payout system or governed self-improvement campaign
has been enabled by this change. The evidence below records the earlier baseline.

## Findings

| Priority | Finding and consequence | Disposition |
|---|---|---|
| Important | `Coordinator.request_work` excluded producer exposure by job ID but review exposure by result ID. A root that released or expired a producer lease could review the successor result. This undermined fresh-review isolation. | Fixed: review eligibility also checks the source producer job's exposure. Regression covers release, expiry, and a replacement key under the same root. |
| Important | `scripts/local_signer.py` only checked the action name before signing. It did not enforce the documented network/root, local lease, artifact bytes, or verdict comparison. | Fixed: helper requires trusted local identity and, for submission, the saved lease, exact artifact file, and verdict. Tests cover changed envelope fields, newline changes, stale lease, and altered context. Local files remain host-writable; this is not a hardened independent signer. |
| Important | The declared `cryptography<47` range resolved to 46.0.7, which the live advisory service flagged. The virtual environment also contained flagged pip 25.3. | Updated to cryptography 50.0.1 and pip 26.2.1; clean follow-up `pip-audit`. The original report contained duplicate advisory records. No claim that every reported vulnerability was reachable through DAIA's Ed25519-only path. |
| Important | The MCP resource/issuer and host/origin rules were hardcoded to loopback. A direct private reverse proxy was not a supported configuration. | Added explicit `serve-mcp --tailnet-url` for one exact `.ts.net` MCP endpoint. Authentication, body limits, DNS-rebinding protection and loopback binding remain enforced. No public listener or Funnel. |
| Important | No MCP test was installed or run by the original CI configuration. Core/REST green checks could not establish SDK interoperability. | Added real-socket SDK tests; CI now installs the pinned MCP SDK and runs them. A successful new GitHub Actions run has not been observed. |
| Important, open | A general contribution host still lacks an OS-backed key store, independent signing approval, and a tamper-resistant consent budget. A model with arbitrary local shell access can replace its saved inputs. | Restrict this pilot to explicitly authorized, bounded factorization data. General autonomous code/proof work remains blocked on an isolated runner and stronger host integration. |
| Important, open | Production ingress controls, OAuth/OIDC, full dependency lock/license review, and cross-process production persistence are absent. SQLite serializes even reads with `BEGIN IMMEDIATE`; MCP tools run coordinator calls synchronously. | Suitable for a small trusted development pilot, with no throughput or public-deployment claim. Add contention, load, cancellation and resource-exhaustion testing before expanding admission. |
| Follow-up, open | An inconclusive review completes its job without scheduling replacement/adjudication. A disputed result also has no implemented recovery workflow. | Such candidates can remain unresolved. The roadmap already calls for bounded retries/adjudication; do not weaken quorum to work around starvation. |

The dependency update was checked against the [upstream cryptography changelog](https://cryptography.io/en/latest/changelog/).

## Executed checks

- Original suite on Windows: **54 passed, 1 skipped** (POSIX permission test).
- Updated suite: **77 passed, 1 skipped**, including real HTTP/MCP sessions and signer checks.
- Deterministic demo: three jobs, one result, final `promoted` state.
- SDK clients: key registration, sticky assignments, heartbeat, signed result submission,
  idempotent replay, producer/reviewer progression to promotion.
- HTTP/MCP boundaries: missing/invalid bearer tokens, wrong Host/Origin, oversized request,
  session reuse by a different root, and revoked grants rejected.
- Live private endpoint: unauthenticated request returns **401**.
- Codex CLI app-server MCP inventory: seven tools; `bearerToken` authentication.
- Supplied SDK probe: passed against the actual private endpoint without taking work.
- Live MCP bootstrap: a separate one-assignment deterministic producer registered, signed,
  and submitted a valid candidate through the tailnet endpoint. Its producer grant was then
  revoked. The two human-launched clients subsequently completed the reviews: the local
  grant submitted adversarial `pass`; the dedicated remote grant submitted reproduce `pass`.
  Both distinct review roots were verified against their private invite records without
  displaying secrets. All three jobs are completed and the candidate is **promoted**.
  The user reports the remote execution occurred on the second physical machine. This
  establishes the bounded pilot outcome, not device attestation or independent people.
- `pip check`: no broken requirements. `pip-audit --skip-editable`: no known vulnerabilities
  after upgrades. The local editable DAIA package is covered by code review, not a registry advisory.
- Native wheel built successfully for the private test kit.
- Tracked/history privacy scan passed (45 blobs, 2 commits). A separate current-worktree
  scan covered 56 tracked/untracked source files with no findings. Syntax compilation,
  PowerShell parsing and `git diff --check` passed. No commit, push or publication performed.

Test fixtures bound graceful server shutdown to two seconds after observing a hanging SSE
shutdown on Windows. This is a test cleanup bound, not proof of production lifecycle behavior.
One upstream Starlette/AnyIO deprecation warning remains.

Key installed versions: Python 3.14, cryptography 50.0.1, MCP/mcp-types 2.2.0,
FastAPI 0.141.1, Starlette 1.6.0, Pydantic 2.13.5, Uvicorn 0.52.4, httpx 0.28.1,
httpx2 2.12.0, pytest 9.1.1, pip 26.2.1, pip-audit 2.10.1. This list is an observed
environment, not a portable dependency lock or a completed license review.

## Pilot operation

Use [the private pilot guide](tailnet-pilot.md) and [one-assignment instructions](pilot-agent.md).
Endpoint, invites, logs, database and machine details belong in private runtime files only.
Three separate test grants can exercise the default producer/two-reviewer policy; they do
not establish independent humans, models, or providers. Two machines alone are not a quorum.
